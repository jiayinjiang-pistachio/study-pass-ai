# 长短期记忆验证手册（前端界面版）

> 适用版本：记忆系统 V2.1（工作记忆 + 短期历史 + 长期画像）
> 设计文档：[`memory-system-v1.md`](memory-system-v1.md)、[`memory-system-v2.md`](memory-system-v2.md)
> 验证方式：**浏览器操作 + 界面反馈**（无需命令行查库）；开发者可选补充项见 §9

---

## 0. 验证范围与界面观测点

| 记忆环节 | 界面观测点 |
| --- | --- |
| 开场白画像表单 | 空会话是否出现卡片、必填校验提示、保存后卡片消失 |
| 长期画像读取 | 让 AI 复述画像；换新会话后回答一致 |
| 长期画像写入（对话回填） | 跳过卡片后对话，再新建空会话，卡片是否消失 |
| 工作记忆（会话内） | 多轮问答上下文连续；刷新页面后仍记得 |
| 会话隔离 | A 会话说过的内容不会出现在 B 会话 |
| RAG 与画像意图 | AI 回复下方「参考了 N 个知识片段」面板的有无 |
| 内部状态（Redis key、TTL、摘要、抽取调用） | **前端不可见**，由自动化测试覆盖（§9） |

> 重置某个场景：右上角「退出登录」→ 注册新账号。前端没有删除 / 编辑画像的入口，已保存的画像只能通过新账号或对话自动抽取来改变。

## 1. 准备工作

### 1.1 启动服务

```bash
# 终端 1：后端（需 MySQL / Redis 已启动）
cd agent-backend && source .venv/bin/activate
uvicorn app.main:app --reload --reload-exclude 'logs/*' --port 8000

# 终端 2：前端
cd agent-frontend
pnpm dev
```

浏览器打开 `http://localhost:5173`（Vite 默认端口，`/api` 已代理到 8000）。

前置检查：

- `.env` 已配置 `MYSQL_URL`、`JWT_SECRET`、`LLM_API_KEY / LLM_BASE_URL / LLM_MODEL`；
- Redis 默认连接 `127.0.0.1:6379` 的 **db1**；
- 首次发送画像类消息时 fastembed 会下载模型，第一轮可能较慢，属正常。

### 1.2 账号与会话

1. 登录页切换到「注册」，用户名 ≥ 3 位，密码 ≥ 6 位且同时含字母和数字，两次密码一致 → 点「注册」。
2. 注册成功后自动登录，默认进入**面试间**。
3. 顶栏可在「学习 / 面试」间切换，两个模块各自维护会话列表，记忆行为一致。
4. 左侧点击「新建会话」→ 新会话自动选中，聊天区进入空状态。

> 新账号没有任何会话时，聊天区显示「暂无会话，点击左侧「新建会话」开始」；**卡片只在有选中会话且消息为空时出现**。

## 2. 场景一：新用户开场白与画像采集

### 2.1 卡片出现

操作：新账号 → 点击「新建会话」。

预期：

- 聊天区出现标题为「先完善一下你的求职画像」的卡片；
- 字段：目标岗位、工作年限、目标职级（必填），已掌握技能、薄弱点（选填）；
- 底部按钮：「稍后再说」「保存并开始」；
- 卡片下方不再显示「暂无聊天记录」。

> 卡片需要等画像接口返回后才出现，网络较慢时可能延迟几百毫秒；若一直不出现，见 §11。

### 2.2 必填校验

操作：不填写直接点「保存并开始」。

预期：字段下方出现红色提示「请填写目标岗位」「请填写工作年限」「请填写目标职级」，且不会出现「画像已保存」提示，卡片保留。

再操作：只填目标岗位和职级 → 保存 → 仍被拦截。

### 2.3 保存成功

操作：

- 目标岗位：`后端开发工程师`
- 工作年限：`3`
- 目标职级：`P6`
- 已掌握技能：输入 `Python` 回车，再输入 `MySQL` 回车
- 薄弱点：输入 `分布式` 回车

点「保存并开始」。

预期：

- 右上角提示「画像已保存」；
- 卡片消失，聊天区显示「暂无聊天记录」；
- 在输入框提问，回复能自然参考岗位 / 年限（不要求逐字复述）。

### 2.4 0 年经验是有效值

操作：新账号 → 新建会话 → 工作年限填 `0`，其余两项填任意值 → 保存。

预期：保存成功，卡片消失（0 不会被当成「未填写」）。

### 2.5 资料已填后不再出现卡片

操作：

1. 保存成功后，再点「新建会话」→ 卡片**不出现**；
2. 浏览器刷新（F5）→ 重新选择刚才的会话 → 卡片**不出现**；
3. 切换到「学习 / 面试」另一个模块并新建会话 → 卡片**不出现**（画像跨模块共享）。

### 2.6 选填项限制

操作：技能连续输入超过 20 项，或单项超过 50 字。

预期：超过 20 项时字段下方提示「最多填写 20 项」；单项超长提示「单项不超过 50 字」，卡片不会保存成功。

## 3. 场景二：长期画像的读取与跨会话延续

前置：账号已完成 §2.3。

### 3.1 单会话内复述画像

操作：发送：

```text
请先复述你目前了解到的我的求职画像信息，再给一条学习建议。
```

预期：回复包含「后端开发 / 3 年 / P6」等信息（技能、薄弱点可能被自然提及），而不是「你还没有提供信息」。

### 3.2 跨会话延续（长期记忆的关键证据）

操作：

1. 点击「新建会话」（消息为空）；
2. 发送同样的问题。

预期：新会话仍然能复述同样的画像。**跨会话仍记得 = 长期画像已注入**。

### 3.3 对话补充画像

前置：沿用当前账号，发送：

```text
我最近开始重点准备分布式系统，薄弱点补充为分布式和消息队列；我更喜欢看视频和做项目来学习。
```

预期：

- 回复正常，且回复下方**没有**「参考了 N 个知识片段」面板（画像类表达不触发检索）；
- 等待 3–5 秒（后台抽取是异步的）；
- 新建空会话，再次让 AI「复述画像 / 推荐学习方式」→ 回复体现「视频、做项目」或补充后的薄弱点。

> 抽取由模型决定，个别字段可能漏抽；只要出现至少一项新信息即可判定链路生效。
> 前端没有画像编辑页，本场景也是验证「画像可被对话更新」的主要方式。

## 4. 场景三：跳过开场白后的自动回填

这是「前端表单为主、对话抽取为辅」的核心场景。

操作：

1. 注册新账号 → 新建会话 → 点「稍后再说」；
2. 卡片消失，显示「暂无聊天记录」；
3. 发送：

```text
我是 3 年后端开发，目前目标职级 P6，熟悉 Python 和 MySQL。
```

4. 等回复结束后**再等 3–5 秒**（后台线程写库）；
5. 点击「新建会话」（空会话）；
6. 若卡片瞬间闪出，等待 1–2 秒（前端会重新拉取画像）。

预期：

- 卡片最终**消失**（说明三项必填已被回填齐全）；
- 在新会话里问「我的目标岗位、工作年限、目标职级是什么？」→ 回复能说出后端 / 3 年 / P6；
- 若卡片仍然存在，说明至少一项未抽到：回到会话补充一句更明确的表述（如「我的目标岗位是后端开发工程师」），等待后再验证。

补充验证（短回答也能回填）：

1. 新账号 → 跳过卡片；
2. 发送「我的目标岗位是后端开发工程师，工作年限 3 年，目标职级 P6」；
3. 等待后新建空会话 → 卡片消失。

> 单字消息不会触发回填：新账号跳过卡片后只发送「好」，再新建空会话，卡片**仍然出现**（三项必填仍缺失）。

## 5. 场景四：工作记忆（同一会话的短期上下文）

前置：任意已登录账号，新建会话 A。

操作与预期：

1. 发送「我叫小林，正在准备后端方向的面试，请记住。」→ AI 回复；
2. 发送「我计划先复习 MySQL 索引，再复习事务隔离级别。」→ AI 回复；
3. 发送「我最开始告诉你的名字和面试方向是什么？」→ 回复应包含「小林 / 后端」（说明会话内上下文生效）。

### 5.1 切换会话不串味

1. 新建会话 B（会自动选中）；
2. 发送「我叫什么名字？」→ 回复**不应**说出「小林」（会话隔离）；
3. 回到左侧「历史会话」点击会话 A；
4. 再问「我叫什么名字？」→ 又能正确回答。

### 5.2 刷新页面后仍记得

1. 在会话 A 中刷新页面（F5）；
2. 登录态保留，左侧列表重新加载，默认选中最新会话（可能是 B）；
3. 手动点击会话 A，发送「我们刚才聊到哪了？我准备复习什么？」。

预期：回复提到「MySQL 索引 / 事务隔离级别」等前文内容（工作记忆存在 Redis，页面刷新不影响）。

### 5.3 会话删除后不再出现

1. 鼠标悬停左侧会话项 → 出现「重命名 / 导出 / 删除」图标；
2. 点删除图标 → 确认框「确定删除会话「…」吗？」→ 点「删除」，提示「已删除」；
3. 刷新页面 → 该会话及其上下文不再出现。

> 工作记忆 TTL 为 8 小时，前端无法等待过期，此参数由自动化测试覆盖。

## 6. 场景五：RAG 与画像意图的区分（可选，需要知识库）

前置：新账号，**跳过了开场白**（必填缺失），并在会话里上传一份学习资料：

1. 点击输入框左侧回形针 → 弹出「上传文档」；
2. 拖入 / 选择 PDF / DOC / DOCX / TXT（≤10MB）；
3. 文档类型选「学习资料」→ 提交，提示「文档上传成功」；
4. 等待几秒（后台异步解析、分块、入库）。

验证：

| 操作 | 预期 |
| --- | --- |
| 提问文档中确实存在的内容（如「请总结这份资料里关于索引的部分」） | 回复下方出现可展开的「参考了 N 个知识片段」面板（必填缺失**不跳过**检索） |
| 发送「我想转行做后端开发，目标是 P6」 | 回复下方**没有**来源面板（画像意图跳过检索） |
| 等待后新建空会话 | 卡片消失（后台完成画像回填） |

> 若知识点问题也没有来源面板：确认文档已提示上传成功、问题与文档内容直接相关、入库已等待足够时间；没有知识库时该场景无法用界面验证，跳过即可。

## 7. 场景六：异常与降级

| 操作 | 预期界面表现 |
| --- | --- |
| 停止 Redis 后继续提问 | 对话正常；当前轮仍能回忆起历史（回源 MySQL）；日志有降级提示（§9） |
| 停止后端服务后发送消息 | AI 消息显示「生成失败」，并弹出错误提示 |
| 未配置 `LLM_*` 时发送消息 | 弹出「AI 服务未配置，请联系管理员」，AI 消息显示「生成失败」 |
| 抽取失败（模型超时 / 格式错误） | 界面无异常；新建空会话卡片仍在（未回填），需重新发送明确表述 |

## 8. 界面验证的边界

以下内部状态**无法从前端界面直接看到**，以自动化测试为准：

- Redis key `memory:working:{user_id}:{session_id}` 的原文条数、TTL 续期、删除后的回填；
- 原文超过 8000 字后的摘要生成与「只保留最近 6 条」；
- 短期历史的 8 轮 / 4000 字 / 12000 字预算；
- 意图判断的相似度分数、是否真正发起了后台抽取请求；
- 跳过 RAG 的检索调用次数（界面上只能通过来源面板间接判断）。

对应命令：

```bash
cd agent-backend && source .venv/bin/activate
pytest tests/test_working_memory.py tests/test_long_term_memory.py \
       tests/test_long_term_chat.py tests/test_stream_chat.py -q
pytest -q
```

预期全部通过（当前基线 176 passed）。

## 9. 开发者补充（可选）

需要定位问题或验证接口数据时：

1. **看画像原始字段**：F12 → Network → 提交卡片后查看 `POST /api/profiles` 或 `GET /api/profiles/me` 的响应 `data`（`target_job` / `years_experience` / `target_level` / `target_skills` / `weak_topics`）。
2. **看后台抽取日志**：

   ```bash
   tail -f agent-backend/logs/app.log | grep -E '长期记忆|工作记忆|画像'
   ```

   - `长期记忆已更新 | user_id=… fields=[…]`：抽取成功，`fields` 即写入的字段；
   - `长期记忆更新失败`：后台线程异常；
   - `读取工作记忆失败，降级为 MySQL 历史`：Redis 不可用；
   - `工作记忆总结失败，暂不裁剪`：摘要模型失败，原文保留待重试。

3. **看工作记忆内容**（可选）：

   ```bash
   redis-cli -n 1 GET memory:working:<user_id>:<session_id> | python3 -m json.tool
   ```

## 11. 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 新建会话没有卡片 | 画像接口失败 / 未加载；或该会话已有消息 | 刷新页面重试；确认是新会话；检查后端与网络请求 |
| 卡片一闪而过 | 进入空会话会重新拉取画像，刷新完成后隐藏 | 属正常，等待 1–2 秒 |
| 保存后卡片又出现 | 三项必填未齐全（0 有效）；保存请求失败 | 确认三项都已填；看是否有「画像已保存」提示 |
| 对话回填后卡片仍在 | 后台抽取未抽全，或等待时间不足 | 等 3–5 秒；补充更明确的表述后新建会话再验证 |
| AI 复述不出画像 | 画像三项不全（表单未保存且未回填） | 先完成 §2.3 或 §4 |
| 新会话还记得名字 | 名字被写进了画像（如本人在表单 / 对话中描述） | 用不涉及姓名的内容做隔离测试 |
| 来源面板从不出现 | 文档未入库 / 问题与文档无关 / RAG 未配置 | 等入库完成；直接询问文档原文内容 |
| 每条消息都提示失败 | 后端未启动 / 代理地址错误 / 令牌过期 | 检查后端与 Vite 代理；重新登录 |
| 首次画像类消息很慢 | fastembed 首次下载模型 | 等待下载完成，后续恢复 |
